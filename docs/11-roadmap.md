## 2. 阶段详解

### 阶段 Demo —— 验证可行性

**唯一目的**：证明「能聊 + 插件能跑 + 一键导入能通」这三件事在技术上成立，且架构不留坑。

| 关键任务 | 说明 |
|---|---|
| `plugin_core` 纯 Dart 包 | manifest 解析、权限守门人、工具注册表、Bridge 编解码、Zip Slip 防护 —— **全部单测覆盖** |
| 最小聊天页 | 输入框 + 消息列表 + 流式渲染 |
| SQLite 持久化 | sessions / messages 两表 |
| 本地 zip 安装 | 选文件 → 校验 → 权限弹窗 → 解压 → 注册 |
| WebView + Bridge | 能跑 `index.js`，能调 4 个原语 |
| 三个测试插件 | 时间插件 / 翻译按钮 / 小游戏 |
| **不做** | 商城、支付、MCP、记忆、人设导入、美化包、多模型、后端 |

**为什么先做 `plugin_core` 而不是先做 UI**：Demo 的技术风险集中在插件内核（校验、权限、Bridge、沙箱），这些是纯逻辑，能在桌面单测。先把这部分测透，可以把「插件装不上」的调试域从五层混合压缩到一层。

### 阶段 1 —— 最小聊天 App

- 多会话：新建 / 切换 / 重命名 / 删除 / 归档
- 消息分页懒加载（1000 条不掉帧）
- Markdown 渲染 + 代码块高亮
- 重新生成 / 编辑重发 / 复制
- 高级设置（隐藏入口）：供应商 / Key / Base URL / 模型名
- FTS5 消息搜索

### 阶段 2 —— 一键人设

- TavernAI 角色卡解析（PNG `tEXt`/`iTXt` chunk 内嵌 JSON，JSON 直读）
- 角色库管理
- **分享链接**：`tsukiro://persona?url=...` 深链接，点开即导入
- 人设包（`provides.personas`）通过插件分发

### 阶段 3 —— 充值闭环

- 网关：FastAPI + LiteLLM，多上游路由 + 降级 + 健康检查
- 鉴权、限流、计费、日志
- 点数体系：充值 → 到账 → 按 token 扣减
- 卡密：生成（只存哈希）+ 兑换（事务 + 行锁 + 幂等 + 限流）
- 账单页
- **本阶段起客户端不再需要用户自己的 Key**

### 阶段 4 —— 插件商城 MVP

- `registry/index.json` 中心索引 + PR 审核流程
- Ed25519 签名 + GitHub Actions 自动打包签名
- 多镜像：jsDelivr / ghproxy / 自建 CDN，客户端测速切换
- L1 配置级插件：纯 JSON，声明原语直映射工具
- Skills 提示词包

### 阶段 5 —— WebView 插件完整化

- 全部 9 个插槽
- 覆盖层（悬浮球、字幕层）
- 插件独立窗口（桌面可拖动缩放）
- 小游戏生态起步

### 阶段 6 —— 系统操作

- 完整原语层（19 个域）
- 权限分级（install / confirm / denied）
- 网络白名单强制
- 系统权限与插件权限的两层模型
- 审计日志 UI

### 阶段 7 —— 记忆 + MCP Client

- `MemoryProvider` 接口 + 默认实现（sqlite-vec 向量检索）
- 历史压缩策略
- MCP Client：JSON-RPC over SSE / WebSocket
- MCP Server 预留接口

### 阶段 8 —— 支付自动化

- 支付宝 / 微信商户 / Stripe
- 自动发卡
- 对账与异常订单处理

### 阶段 9 —— 生态运营

- 审核后台、举报、下架、评分
- 美化包上架
- L7 Harness 级开放（`registerStep` / `registerRuntime`）

## 3. Demo 验收门槛（硬性）

四条流程**全部**通过：

```
✅ 流程 1  打开 App → 能聊天 → 消息存本地（杀进程重启后仍在）
✅ 流程 2  装「时间插件」→ 问「现在几点」→ 模型调 get_time → 返回正确时间
✅ 流程 3  装「翻译按钮」→ 聊天页工具栏多出「翻译」→ 点击 → AI 翻译上一条消息
✅ 流程 4  装「小游戏」→ 打开独立窗口 → 在窗口里通过 Bridge 和 AI 对话
```

附加约束（决定 Demo 是否「做对了」而不只是「跑起来了」）：

| 约束 | 验证方式 |
|---|---|
| 插件拿不到 API Key | 插件代码里无法构造出带 Key 的请求；`model.chat` 参数 schema 无 Key 字段 |
| 权限撤销立即生效 | 撤销 `sys.time` 后，问时间 → 模型收到 `PERMISSION_DENIED` |
| 沙箱不可越界 | 插件尝试 `fs.read({path:'../../secret'})` → `SANDBOX_VIOLATION` |
| Zip Slip 被拦 | 构造含 `../evil.txt` 的 zip → 安装被拒 |
| 插件崩溃不传染宿主 | 插件 `index.js` 抛未捕获异常 → 宿主正常，插件标为已停用 |
| 未实现原语优雅降级 | 调用 `media.listPhotos` → `UNSUPPORTED`，不是崩溃 |

## 4. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| WebView 在低端机性能差 | 插件卡顿，体验崩 | 插件 WebView 懒加载；声明式控件不付 WebView 成本；主界面纯原生 |
| 插件生态起不来 | 没有差异化 | 先做人设包（圈内创作者最想要），插件次之；L1 配置级零代码门槛 |
| 恶意插件 | 用户信任崩塌 | 宿主侧守门人 + 沙箱 + 审计可见 + 商店审核 + 确认级权限 |
| 上游 API 不稳定/涨价 | 服务不可用 | 多源冗余 + 自动降级（原则 6） |
| 合规风险（AI 陪伴内容） | 下架 | 明确虚拟商品售出不退；内容策略提前规划（未排期，标记为待办） |
| 点数被刷 | 亏钱 | 网关侧计费 + 客户端限流 + 插件调用上限（原则 5） |
