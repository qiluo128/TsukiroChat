# 01 · 项目概览

## 1. 项目定位

**Tsukiro Chat** 是面向**人机恋 / AI 陪伴圈子**的轻量、低门槛聊天平台。

| 维度 | 说明 |
|---|---|
| 目标用户 | 人机恋 / AI 陪伴圈内用户，以及圈内的角色卡创作者、插件作者 |
| 核心卖点 | **点击即用**——下载后 30 秒内开始对话，不需要找 API 站、配 Key、填 URL |
| 第二卖点 | **插件自由扩展**——宿主只做底座，插件做一切 |
| 商业目标 | 覆盖服务器成本即可，不追求规模化收入 |
| 生态目标 | 给圈内人一个干净的选择，顺带叠知名度；先让圈内创作者用起来 |

### 1.1 差异化

现有同类产品的普遍痛点：

- 需要自己去买 / 找 API Key，填 Base URL，配置模型名 —— 门槛劝退。
- 插件能力要么没有，要么只能改提示词，无法操作手机、无法加 UI。
- 角色卡分发靠离线文件，分享链路长。

Tsukiro Chat 的三条应对：

1. **点数替代 Key**：用户充值点数，按 token 计费，完全不感知 API 供应商。
2. **原语化插件框架**：宿主提供原子原语 + 权限守门人 + WebView 沙箱，插件组合出任意能力（L1–L7）。
3. **人设包可分享链接**：点开链接即进 App 加载，自带传播属性。

## 2. 两条路径

```
【默认路径】面向 95% 用户
下载 App ──▶ 打开就能聊（内置默认人设 + 赠送体验点数）
        ──▶ 点数用完了
        ──▶ 点「充值」──▶ 跳转/加 V ──▶ 付款 ──▶ 点数到账
        ──▶ 继续聊

【高级路径】面向极客 / 自建用户，默认隐藏
设置 ──▶ 高级 ──▶ 配置供应商 / API Key / Base URL / 模型名
```

**设计红线**：默认路径上不允许出现任何技术术语（Key、URL、Token、模型 ID）。

## 3. 核心设计原则

原始清单 11 条，此处补充**实现含义**，以便落地时不被误读。

| # | 原则 | 实现含义 |
|---|---|---|
| 1 | 默认路径极简 | 首次启动零配置进聊天页；体验点数由后端下发；任何配置项都不得阻塞首屏 |
| 2 | 高级设置隐藏 | 「高级」入口需在设置页二级菜单；默认折叠；不看文档也能用 |
| 3 | 点数替代 Key | 客户端只需一个用户 Token；模型名走网关的「逻辑模型名」，不是上游真实模型名 |
| 4 | **密钥只在后端** | 上游 Key 只存在于网关环境变量 / KMS；客户端二进制内不得含任何上游 Key |
| 5 | 计费以网关为准 | 客户端上报的 token 数只用于 UI 展示；真实扣费由网关按响应 usage 计算，客户端不可信 |
| 6 | 多源冗余 | 网关维护多个上游 Provider，按健康检查 + 权重路由，失败自动降级 |
| 7 | **插件不碰钱和 Key** | 插件调模型只能走 `model.chat` 原语，宿主转发到网关；插件 manifest 里没有地方能写 Key |
| 8 | 框架尽可能底层 | 原语原子化（`fs.read` 而不是 `loadCharacterCard`），插件自行组合 |
| 9 | 权限安装时授权 | 安装时一次性弹窗；同意后运行时不再打扰；可随时撤销；撤销立即生效 |
| 10 | 底层留框架 | 现在只开放「工具注册」；`registerStep` / `registerRuntime` 接口先定义好，L7 放开时不重构 |
| 11 | 生态靠口碑 | 人设包 / 插件分享链接要能一键落地；先服务圈内创作者 |

## 4. 自由度七层

宿主不预设插件能做什么，只限定插件**不能碰什么**。能力从「改配置」到「接管 Agent 循环」逐级开放。

| 层级 | 名称 | 插件做什么 | 宿主提供什么 | 状态 |
|---|---|---|---|---|
| **L1** | 配置级 | 只声明配置，不写代码：人设包、Skills 提示词包、美化包、原语直映射工具 | manifest 解析、配置注入、原语映射执行器 | 规划中 |
| **L2** | 工具级 | 声明工具，模型函数调用触发：查天气、翻译、读文件、调远程 API | 工具注册表、函数调用循环、`model.chat` 原语 | **Demo 实现** |
| **L3** | UI 级 | 往宿主 UI 塞东西：工具栏按钮、设置分区、独立页面、覆盖层 | 插槽系统、WebView 容器、Bridge | **Demo 实现** |
| **L4** | 系统级 | 通过原语操作手机：文件、相册、摄像头、通讯录、短信、定位、通知、截屏、无障碍 | 原语层 + 权限守门人 + 原生能力封装 | 预留（接口先定义） |
| **L5** | MCP 级 | MCP Client 接远程 Server；MCP Server 暴露自身能力 | MCP 连接器（JSON-RPC over SSE/WS）、本地 HTTP 运行时 | Client 预留 / Server 预留 |
| **L6** | 记忆级 | 实现 `MemoryProvider`：自定义存储、检索、压缩、管理 UI | 记忆接口契约 + 调用时机 | 预留 |
| **L7** | Harness 级 | 接管 Agent 循环：多步推理、工具调用策略、多角色协作 | `registerStep` / `registerRuntime` | **仅留接口** |

### 4.1 能力上限公式

> **插件自由度上限 = 宿主原语的丰富度 + 权限模型的精细度 + 沙箱的安全度**
>
> 原语越原子，插件越自由。

这是整个插件框架的设计纲领：不要在宿主里写「查快递插件」，要写 `net.request`。

## 5. 插件边界

### 5.1 插件能做

- 用任何原语组合出任何工具
- 往任何插槽放 UI（按钮、菜单项、分区、独立页面、覆盖层）
- 接任何远程 MCP Server
- 实现任何记忆策略（L6 放开后）
- 未来接管 Agent 循环（L7 放开后）

### 5.2 插件不能做

| 禁止项 | 强制手段 |
|---|---|
| 直接调系统 API | 沙箱 WebView 无原生绑定，只能通过 Bridge 走宿主原语 |
| 接触 API Key | manifest 无此字段；`model.*` 原语由宿主代发，插件拿不到凭据 |
| 读写其他插件的数据 | 每个插件独立目录 + 独立 `state` 命名空间，路径由宿主拼接，插件无法越权 |
| 绕过权限校验 | 权限校验在**宿主侧**执行（不在 WebView 侧），撤销后调用立即 `PERMISSION_DENIED` |
| 伪装成宿主 UI | 插件 UI 必须渲染在宿主提供的容器内，且带可辨识标记（图标 / 边框 / 标题栏） |
| 静默联网 | 网络白名单：manifest 声明 `network.allow`，不在白名单的域名请求被宿主拒绝并记审计 |

## 6. 术语表

| 术语 | 含义 |
|---|---|
| **宿主 / Host** | Tsukiro Chat 主 App，负责 UI、存储、原语、权限、网关通信 |
| **插件 / Plugin** | 一个 zip 包，含 `manifest.json` + JS/HTML 资源，在沙箱 WebView 中运行 |
| **manifest** | 插件的声明式描述文件，声明 id/版本/权限/提供的工具与 UI |
| **原语 / Primitive** | 宿主暴露给插件的最小能力单元，如 `fs.read`、`sys.time` |
| **插槽 / Slot** | 宿主预埋的 UI 挂载点，如 `chat.toolbar` |
| **Bridge** | WebView ↔ 宿主 的双向消息通道，承载原语调用与事件 |
| **权限守门人 / Gatekeeper** | 宿主侧唯一的权限校验点，所有原语调用必经 |
| **sandbox 目录** | 每个插件独立的文件空间，`fs.*` 原语被限制在此目录内 |
| **工具 / Tool** | 插件声明、暴露给模型的函数，模型通过 function calling 触发 |
| **Skill** | 提示词包 + 工具白名单的组合，L1 级能力 |
| **人设 / Persona** | 角色设定、开场白、示例对话；兼容 TavernAI 角色卡 |
| **点数 / Credit** | 用户充值得到的余额，按 token 消耗扣减 |
| **网关 / Gateway** | 后端 API 聚合层，持有上游 Key，做路由、鉴权、限流、计费 |
| **会话 / Session** | 一次持续对话，含消息列表与人设绑定 |
| **审计日志 / Audit Log** | 所有原语调用的记录，用于追溯与用户自查 |

## 7. 成功标准

### 7.1 Demo 阶段（当前）

四个流程**全部**跑通才算成功：

```
1. 打开 App → 能聊天 → 消息存本地（重启不丢）
2. 装「时间插件」→ 问「现在几点」→ 模型调工具 → 返回时间
3. 装「翻译按钮」→ 聊天页多出按钮 → 点击 → AI 翻译
4. 装「小游戏」→ 打开独立窗口 → 在窗口里通过 Bridge 和 AI 对话
```

### 7.2 长期

- 新用户从下载到发出第一条消息 **< 30 秒**，且未接触任何技术配置。
- 插件作者能在**不看宿主源码**的情况下，仅凭 `docs/04`–`docs/08` 写出一个可用插件。
- 宿主升级不破坏已发布插件（manifest 版本化 + 向后兼容策略）。
