# 02 · 需求规格

编号规则：`FR-<模块>-<序号>` 功能需求，`NFR-<类别>-<序号>` 非功能需求。
优先级：**P0** = Demo 必须；**P1** = 首个正式版必须；**P2** = 成长阶段。

模块代号：`HOST` 宿主 App · `PLG` 插件框架 · `MKT` 插件商城 · `GW` 网关 · `PAY` 支付 · `PER` 人设 · `MEM` 记忆。

## 6. 非功能需求

### 6.1 性能

| 编号 | 需求 |
|---|---|
| NFR-PERF-01 | 冷启动到可输入状态 < 2 秒（中端安卓机） |
| NFR-PERF-02 | 发送消息到首个 token 渲染 < 800ms（不含上游排队） |
| NFR-PERF-03 | 消息列表 1000 条时滚动不掉帧（60fps），需分页/懒加载 |
| NFR-PERF-04 | 插件 WebView 冷启动 < 500ms；常驻插件进程内存占用 < 60MB |
| NFR-PERF-05 | 原语调用宿主侧开销（不含网络）< 5ms |

### 6.2 安全

| 编号 | 需求 |
|---|---|
| NFR-SEC-01 | 上游 API Key 不得出现在客户端二进制、本地存储、日志中 |
| NFR-SEC-02 | 插件 WebView 禁用 `file://` 越权访问、禁用任意 `fetch`（仅白名单代理） |
| NFR-SEC-03 | 插件 `fs.*` 只能访问自己沙箱目录，路径穿越（`..`）必须被规范化拒绝 |
| NFR-SEC-04 | 插件包解压必须防 Zip Slip（绝对路径 / `..` 条目拒绝） |
| NFR-SEC-05 | 用户 Token / 点数凭据存安全存储（Keychain / EncryptedSharedPreferences） |
| NFR-SEC-06 | 所有原语调用写审计日志（时间、插件、原语、参数摘要、结果、耗时） |
| NFR-SEC-07 | 商城插件包 sha256 + Ed25519 验签（阶段 4 起） |
| NFR-SEC-08 | 极高风险权限（无障碍、短信、通话、截屏）标记为「每次确认」级别 |

### 6.3 隐私

| 编号 | 需求 |
|---|---|
| NFR-PRIV-01 | 对话默认只存本地，不上传（除非用户显式启用云同步） |
| NFR-PRIV-02 | 插件访问敏感数据前必须已获授权，且授权理由对用户可见 |
| NFR-PRIV-03 | 审计日志本地可查、可清空 |
| NFR-PRIV-04 | 上架商店的插件需提供隐私声明（采集哪些数据、用途） |

### 6.4 兼容与可维护

| 编号 | 需求 |
|---|---|
| NFR-COMP-01 | manifest 带 `manifestVersion`，宿主按版本兼容策略加载 |
| NFR-COMP-02 | 新增 manifest 字段必须是可选的，删除字段需走大版本 |
| NFR-COMP-03 | 插件 API 遵循语义化版本，破坏性变更升 major |
| NFR-COMP-04 | 最低支持 Android 8.0（API 26）/ iOS 14 |
| NFR-COMP-05 | 宿主必须优雅处理插件崩溃：插件崩溃不影响宿主，仅停用该插件并提示 |

### 6.5 可用性

| 编号 | 需求 |
|---|---|
| NFR-UX-01 | 首次启动无任何必填配置项 |
| NFR-UX-02 | 默认路径不出现技术术语（Key / URL / Token / 模型 ID） |
| NFR-UX-03 | 所有错误给出人话提示 + 可执行的下一步 |
| NFR-UX-04 | 插件 UI 必须可辨识（不能伪装宿主原生界面） |
