# 26 · 逐智能体的配置（插件 / MCP / 工具）

> 状态：**先记录，不实现**。等正式 UI 阶段再做。
> 结论：**不需要大改**，但有一个语义必须先想清楚。

---

## 1. 现状：所有配置都是**全局**的

| 项 | 在哪 | 作用域 |
|---|---|---|
| 插件安装/启用 | `PluginHost._plugins[].enabled` | 全局 |
| 插件权限授予 | `gatekeeper._granted[pluginId]` | 全局（按插件） |
| 插件工具 | `ToolRegistry` | 全局 |
| MCP 连接 | `mcp.connections`（settings 一条 JSON） | 全局 |
| MCP 工具 | `ToolRegistry`（`pluginId = mcp:<id>`） | 全局 |

**结果**：装了「天气插件」，每个智能体都能用；配了「麦当劳 MCP」，
每个智能体的模型都能看到那 35 个工具。

对一个"多智能体各有人格"的应用来说，这不对 ——
你给 A 配的插件，B 不该也看得见。

---

## 2. 需求拆成两件**语义不同**的事

这是本文档最重要的一节。很多人会把它们混在一起，但代价差一个数量级。

### ① 可见性（Visibility）

> **不把这个工具「offer」给 A 的模型。**

实现：在 `toOpenAiTools` 上加一个过滤集合。
模型看不到 = 调不了（它只能调我们给的）。

### ② 授权（Authority）

> **这个插件对 A 完全不可用** —— 包括它的钩子、UI 插槽、后台任务。

实现：`gatekeeper.check` 要加 `agentId` 维度，所有调用点都传。

---

## 3. 改动量对比

| | 可见性 | 授权 |
|---|---|---|
| 数据 | 一张 `agent_scope`（agentId + 目标 id + 开关） | 同左 |
| 工具过滤 | `toOpenAiTools(allowed:)` + 2 处调用点 | 同左 |
| UI 插槽过滤 | `visibleUi` 已带 `agentId`，加一步集合判断 | 同左 |
| **门禁** | **不动** | **要加维度**：`check(pluginId, perm, {agentId})`，全仓十几处调用 |
| 钩子 | 不动（插件仍会收到） | 要按 agent 过滤 |
| 后台任务 | 不动（插件仍在跑） | 要能停 |
| 估算 | **小**（半天） | **大**（门禁是安全核心，改错就是洞） |

---

## 4. 结论：先做**可见性**，授权保持全局

理由：

1. 用户的诉求（"每个智能体用不同的插件/MCP"）**本质上就是可见性** ——
   模型看不到就不会用。
2. 改门禁是**动安全核心**。这个月已经在权限层犯过几次错（`__host__`
   没登记、`registerExternal` 差点放行所有人），不适合再叠维度。
3. 可见性有**明确的降级行为**：插件还在跑，只是不 offer 给这个 agent。
   这比"部分生效"要好理解。

### 但要写清一条限制

> **可见性 ≠ 授权。** 屏蔽工具**不能**阻止一个插件的钩子和后台行为。

如果将来真有"这个插件绝对不许碰 A"的需求，那才需要做授权维度。
现在没有这个需求。

---

## 5. 需要的数据（最小）

```sql
-- 一条表覆盖两种开关，goal 用字符串区分
CREATE TABLE agent_scope (
  agent_id TEXT NOT NULL,
  target   TEXT NOT NULL,   -- 'plugin:<id>' | 'mcp:<connectionId>'
  enabled  INTEGER NOT NULL DEFAULT 1,
  PRIMARY KEY (agent_id, target)
);
```

**默认语义**：没有行 = 用全局设置。这样老用户升级后行为不变
（全局装了就用），不会突然所有插件都"消失"。
