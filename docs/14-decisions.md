# 14 · 架构决策记录（ADR）与待定问题

---

## 第一部分：已定决策（ADR）

### ADR-001 · 宿主语言选 Flutter + Dart

**状态**：已接受 · **日期**：2026-02

**背景**：需求给出 `Flutter + Dart` 或 `Kotlin + Jetpack Compose` 两个选项。

**决策**：Flutter + Dart。

**理由**：
1. 一套代码覆盖 Android + iOS，iOS 版本不需要重写（需求虽未排期 iOS，但不应把路堵死）。
2. **关键理由**：插件内核可以用纯 Dart 写，无 Flutter 依赖，从而能在桌面用 `dart test` 单测。这是 Demo 风险最大的部分，能单测意味着风险大幅下降。
3. WebView 集成成熟（`flutter_inappwebview`）。

**代价**：包体积比原生大（约 +8 MB）；低端机上滚动性能不如原生 —— 已通过 NFR-PERF-03 与「声明式插槽由宿主渲染」缓解。

### ADR-002 · 插件内核与 Flutter 宿主分仓（同 monorepo 分包）

**状态**：已接受 · **日期**：2026-02

**决策**：`packages/plugin_core` 是纯 Dart 包，**不依赖 Flutter**，作为独立包被宿主引用。

**理由**：
- 可 `dart test` 单测，无需模拟器。
- 强制清晰的依赖边界：内核不会偷偷调用 Flutter API。
- 未来可复用到 CLI 工具、桌面宿主、甚至服务端（如插件包校验服务）。

**代价**：需要维护 `pubspec.yaml` 的 path 依赖；某些功能（如平台判断）需通过依赖注入而非直接调用。

---

### ADR-003 · 权限校验在宿主侧，不在 WebView 内

**状态**：已接受 · **日期**：2026-02

**背景**：直觉做法是「没授权的原语就不注入到 `tsukiro` 对象上」。

**决策**：接口注入仅作便利层，**权威校验在宿主侧 `Gatekeeper`**，对每条 Bridge RPC 重做。

**理由**：JS 层过滤可被绕过（保存函数引用、改原型、直接构造 Bridge 消息）。唯一可靠的位置是宿主。

**代价**：每次原语调用多一次校验（内存查表，实测应 < 1ms）。可接受。

---

### ADR-004 · 宿主内控件由宿主渲染，插件只给声明

**状态**：已接受 · **日期**：2026-02

**背景**：需求提到 `ui.render` 原语，似乎允许插件让宿主动态渲染任意 UI。

**决策**：**不实现 `ui.render`**。改为：
- 宿主内控件 → `manifest.provides.ui` 声明式描述，宿主渲染
- 需要完全自定义 → `manifest.provides.pages` 独立页面（WebView）

**理由**：
1. **视觉一致性**：十个插件十种风格，产品感崩塌。
2. **不可伪装**：原则要求插件 UI 必须可辨识，宿主渲染天然满足。
3. **性能**：声明式控件零 WebView 开销。聊天页工具栏每次都拉起一个 WebView 是不可接受的。

**代价**：插件的 UI 自由度受限。缓解方式：独立页面形态给了完全自由。

### ADR-005 · 工具名冲突加前缀而非覆盖

**状态**：已接受 · **日期**：2026-02

**决策**：后注册的同名工具被重命名为 `<prefix>__<name>`，并写审计。

**理由**：静默覆盖会让先装的插件莫名失效，且极难排查（用户会以为是插件坏了）。显式冲突是可诊断的。

---

### ADR-006 · 用 `archive` + `path` 包而非手写 zip/路径处理

**状态**：已接受 · **日期**：2026-02

**决策**：zip 解析用 `archive`，路径处理用 `path`。

**理由**：Zip Slip 与路径穿越是安全漏洞的重灾区。手写解析容易漏掉符号链接、URL 编码、Windows 大小写、UNC 路径等边界。成熟库 + 自己写防护层 + 充分单测是更稳的组合。

**注意**：即使使用 `archive`，**仍必须自己做 Zip Slip 检查** —— 库只负责解析，不负责安全策略。

---

### ADR-007 · `state.*` 用每插件 JSON 文件而非 SQLite 表

**状态**：已接受 · **日期**：2026-02

**决策**：插件键值状态存 `sandbox/<pluginId>/state.json`，不建数据库表。

**理由**：
- 避免每插件动态建表（schema 管理灾难）。
- 卸载插件 = 删目录，天然干净。
- 100ms 防抖落盘避免高频写 IO。

**代价**：单插件 5 MB 上限（可接受，超大数据应该用 `fs.write` 自己管文件）。

---

### ADR-008 · API Key 存安全存储，绝不进 SQLite

**状态**：已接受 · **日期**：2026-02

**决策**：`provider.apiKey` 用 `flutter_secure_storage`（Keychain / EncryptedSharedPreferences），SQLite 里只存引用标记。

**理由**：SQLite 文件可能被备份、导出、adb backup 拉走。原则 4「密钥只在后端」在 Demo 阶段（用户自填 Key）也必须尽力遵守。

---

### ADR-009 · 先做纯 Dart 内核，后做 Flutter 宿主

**状态**：已接受 · **日期**：2026-02

**决策**：Demo 的第一阶段只做 `plugin_core` 与单测，不碰 Flutter/Android。

**理由**：技术风险集中在插件内核（manifest 校验、权限守门、Bridge、Zip Slip、工具循环），这些是纯逻辑。先单测通过，把「插件装不上」的调试域从五层混合压缩到一层。

**代价**：前几轮看不到界面，需要耐心。但这是刻意的顺序选择。

---

### ADR-010 · Agent 循环从第一天起就拆成可替换步骤

**状态**：已接受 · **日期**：2026-02

**决策**：宿主内部用 `AgentStep` 可替换步骤实现默认循环，即使 Demo 阶段没有任何插件能替换它。

**理由**：原则 10「底层留框架，未来放开 harness 级不用重构」。如果一开始写成一个大函数，L7 放开时需要重写整个循环 —— 那时已有用户在跑，风险高。

|---|---|

### 🟡 Q5 · 聊天数据加密

| 项 | 内容 |
|---|---|
| **问题** | 本地对话是否加密？加密会影响搜索（FTS5 无法直接搜密文）。 |
